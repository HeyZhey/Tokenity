# Tokenity UI Visual Baseline

This checklist records visual-language observations from the eight supplied reference images.
It is intentionally limited to presentation. Existing Tokenity structure, behavior, state, data,
copy, accessibility, and lifecycle rules remain authoritative.

- Use a warm ivory window, a slightly deeper pale-stone sidebar, near-white elevated surfaces,
  graphite text, and quiet hairline borders. Dark mode uses purpose-built graphite layers rather
  than a simple inversion or pure black.
- Keep the bundled Alpine/Cobalt assets as the brand. Use Tokenity's lower-saturation
  mineral-blue tokens for selection, focus rings, links, and primary controls instead of the
  brighter macOS default blue. Reserve green for healthy/normal, orange for warning/in-progress,
  and red for failure or destructive actions.
- Use the system serif face for page titles and primary card titles to create the editorial
  hierarchy visible across all eight references. Keep navigation, body copy, controls, status,
  and tables in the system sans-serif face; use monospaced text for logs, endpoints, IDs, code,
  timestamps, and technical values.
- Build spacing from 4/8/12/16/24/32 points. Preserve the existing sidebar widths, window minimum,
  page margins, maximum content width, information order, interaction paths, and data density.
- Separate content with a slight surface lift and 0.5–1 point border. Prefer 12–14 point card
  radii, 7–10 point control radii, and capsules only for compact pills. Avoid broad shadows,
  gradients, glass effects, oversized KPI blocks, and decorative animation.
- Give selected navigation rows a low-saturation blue fill with blue icon and text. Keep SF
  Symbols consistently sized and line-weighted. Primary buttons use restrained blue fill;
  secondary buttons use bordered or quiet styles; disabled controls remain legible.
- Keep status treatments compact and local. Never tint an entire row to communicate status, and
  never replace actual Tokenity state with a reference-image example.
- Overview and Cluster use calm bordered groups, compact status signals, and restrained network
  linework without importing reference metrics or controls.
- Models and Network retain dense operational rows and real configuration/status data while using
  clearer typographic columns, compact capability pills, and low-noise separators.
- Chat retains its header/transcript/composer/history relationship. Use generous transcript
  whitespace, a restrained user bubble, a bordered assistant response, and the real brand mark for
  assistant/empty states. Preserve streaming, thinking, model lock, history, and follow behavior.
- API Access, Logs, and Settings preserve their current functions and real data. Technical content
  remains monospaced and selectable; no reference-only examples, filters, charts, or statistics
  are added.
- Preserve the tracked PNG lockup and mark variants plus the tracked macOS icon. Verify both
  appearances at small sizes, bundle inclusion, and all existing accessibility
  labels/identifiers.
